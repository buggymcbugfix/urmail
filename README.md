urmail: sending e-mail from Ur/Web
==================================

An Ur/Web library that sends a message through an SMTP server, over
libcurl.  `urmail.urs` is the interface: `message` checks a message, its
addresses (`local@domain` or `Name <local@domain>`), header values,
attachments and images, and gives it or every problem with it, one line
each; `send`, from an io task, sends it and says what became of it (sent,
refused, not sent, maybe sent, or failed before any of it was tried).
Sending is not something a transaction can undo, so there is no sending
from one: a request handler queues the message in a table, and a periodic
task in io claims it and checks it in one transaction, sends, and records
the status in another.  `tests/app/test.ur` and `examples/queue.ur` are
such applications.  Needs an Ur/Web with the `io` monad.

An attachment is a `Blob` (a name, a MIME type the application's `.urp`
must `allow mime`, the bytes) or a `ServedFile`, a file a `file` directive
of the `.urp` serves, by its path, with the directive's bytes and MIME
type.  The attachments go after the body, base64-encoded, in the order
given.  The HTML version is a `page`, written as for a browser: an img
whose src is a path a `file` directive serves gets that file sent with
the HTML, in a `multipart/related` (which clients show where remote
images are blocked), and the src points at it in the mail.  An image that
is not a served file, one the application makes, is given in `Images`
with the url the page uses for it.  The page itself stays as it is, so the
application can serve it to a browser as well.

Building
--------

    ./autogen.sh
    ./configure --with-urweb=PREFIX   # where urweb is installed; defaults to
                                      # the prefix of the urweb on the PATH
    make
    make check                        # the tests, see below
    make install

`configure` finds libcurl through pkg-config.  Everything an application
needs is installed under the prefix: the shared and static library in
`lib/`, `urmail.h` in `include/urweb/`, and in `lib/urweb/ur/urmail/` the
signature and the `.urp` files, so that an application imports the library
with

    library PREFIX/lib/urweb/ur/urmail

`config.urp` there is generated by `configure` and names the header and the
libraries by absolute path, so no `-L` or `-I` flags are needed when the
application is compiled.

With Nix: `nix-build` builds and tests the library against the Ur/Web named
in `urweb-src.nix`; `nix-shell` gives a shell with everything the build and
the tests need.  A project that packages the library calls `derivation.nix`
with its own `urweb`.

Tests
-----

    tests/run.sh [-u] [CASE...]

An Ur/Web application under `tests/app` sends messages to a fake SMTP
server (`tests/smtpd.py`, python, standard library only), and what the
server saw, what the application answered and what it logged are compared
with the case's `expected` file.  A case is a directory under `tests/cases`
with an `args` file describing the server's behaviour, the TLS setting and
the message; `-u` rewrites the expected files.  `URWEB` names the compiler
to use (with the flags in `URWEB_FLAGS`), otherwise the one on the PATH.
The runner needs python3, openssl (a self-signed certificate for STARTTLS),
curl and sqlite3 (the application's queue).  What it builds lands under
`tests/out` of the build tree (`BUILDDIR`; the source tree unless set, and
`make check` sets it), so a build tree apart from the source tree works,
and `make distcheck` with it.  An Ur/Web installed outside the loader's
path, an in-tree build of the compiler installed under its `out/` say,
needs `LD_LIBRARY_PATH` set to its `lib` directory, or the application does
not start; the runner shows the loader's message then.

Debugging
---------

`URMAIL_DEBUG=1` in the application's environment traces every send on
stderr, in the shape of libcurl's verbose output (commands, replies, what
libcurl notes), with the credentials left out and the message not shown.
`URMAIL_TIMEOUT=SECONDS` changes how long a send may go without progress
before it is given up, and for how long an idle connection is kept (100
by default): a whole number of seconds from 1 to 86400; anything else is
reported on stderr and the default used.
